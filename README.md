# 微信飞牛相册

Theos / Objective-C / Logos 插件。在微信聊天的“＋ → 照片”入口选择系统相册或飞牛 NAS 相册，从 NAS 勾选图片，经微信原生素材接口发送。源码与 PyQt6 桌面应用独立。

0.1.1 修复预览后切换原图路径下的异步回调生命周期问题；用户真机复测确认不闪退，原图发送与打开正常。

0.2.0 新增右侧日期快滑条和 NAS AI 搜索。新增功能的真机结果单独记录，不能由此前媒体发送验证推断。

0.2.1 将搜索栏改为独立嵌入页面，去除系统搜索控制器的二次展示；真机后续确认键盘已弹出。0.2.2 修正日期条 UIKit 触摸回调的方法名，并增加真正调用系统回调签名的拖动与松手测试。

0.2.3 使用独立搜索输入弹窗。用户已在 Dopamine iPadOS 15.2 / 微信 8.0.75 真机确认日期拖动与跳转、NAS AI 搜索、从搜索结果发送图片及聊天中打开均正常。曾出现微信原生输入框与插件均不弹键盘，单独重启系统键盘服务后两处恢复；此现象不归结为搜索控件本身已证实的缺陷。

0.2.4 修复全能签修改 Bundle ID 后插件跳过初始化的问题。启动改按微信主程序识别，保留媒体接口检查；修改包名的签名环境仍待重新签名实测。

0.2.5 修复日期跳转后向上滑动回到最新日期：按日期浏览时不再触发重置时间线的下拉刷新；向上接近顶部会补取相邻的较新照片，并保持当前照片在屏幕中的位置。向下继续浏览较早照片。

0.3.0 新增普通视频列表、缓存下载预览和本地视频素材发送适配；顶部增加“分类”，提供人物、地点和媒体类型。媒体类型包含视频、实况、GIF、截图、全景、RAW 和 360° 照片，筛选在 NAS 执行，详情继续每批 60 项。新增功能的真机验收单独记录。

0.3.1 修复视频缓存的读取权限，避免把 iOS 媒体服务无法读取误报成编码不支持；人物列表增加 64 点人脸头像，未命名人物也能按头像辨认。

0.3.2 修复普通视频误取 JPEG 封面作为视频文件：播放与发送优先使用 NAS 返回的 videoUrl，网格仍使用缩略图；实况照片的原图与配对视频逻辑保留。

0.3.3 修复视频进入图片处理回调而卡住的问题：视频生成兼容 MP4 和 JPEG 封面后，通过当前聊天的原生视频消息接口提交；图片、GIF、实况沿用既有入口。常规视频最多生成 1080p 兼容版本，勾选原图时另携带原始视频供微信原视频流程使用，接收端原视频效果仍待单独验证。

0.3.4 新增预览加载遮罩和真实下载百分比，支持照片、视频、GIF 与实况预览。无法获知总大小时显示“加载中”，下载完成后在解析阶段显示“正在打开”，显示成功或出错后关闭遮罩。可继续返回或左右切换。用户已在测试 iPad 上确认进度显示与预览正常。

0.3.5 补齐运行中自动续期：HTTP 401 先用 longToken 续期并保存轮换后的令牌，原请求最多重试一次；并发过期共用一次续期。网络中断、服务暂时出错或续期后仍返回 HTTP 401 都保留凭据，只有长令牌被明确判为失效或主动退出时清除。旧版本已经清除的登录态仍需重新登录一次。

0.3.6 在视频缩略图右下角显示 NAS 返回的时长（分:秒 / 时:分:秒）；缺失时长不显示虚构数值。设置新增「内外网访问」，可选择关闭、自动、内网、外网。填写同一 NAS 的家中 Wi-Fi 名称、内网地址和外网地址；自动模式完全匹配 Wi-Fi 名称时走内网，其他情况走外网。只在打开新相册页或保存设置时切换地址，发送过程中不切换。

读取 Wi-Fi 使用 iOS 官方 NEHotspotNetwork API，需要微信的 `com.apple.developer.networking.wifi-info` 签名权限及系统要求的定位授权等条件。全能签改包后是否保留权限取决于签名与描述文件，注入 dylib 本身不能授予权限。「读取当前 Wi-Fi / 请求定位授权」可检查；主程序缺少定位用途说明时不会发起可能导致崩溃的授权请求。读不到名称时静默走外网，仍可手动选择内网；设置页主动读取 Wi-Fi 时才显示检查结果。不修改微信的签名或用途说明。

内外网两个地址均视为手动配置的同一台 NAS，保存的令牌会用于这两个地址；当前账号 NAS 不在配置中时拒绝复用。地址切换会重新认证并更新会话代际，媒体 URL 仅允许在明确配置的别名之间重绑定，其他来源仍拒绝请求。外网反向代理应保留 NAS 的 HTTP / WebSocket 路径。

0.3.7 补齐普通视频与实况预览的音频会话：播放前启用 Playback / MoviePlayback 并激活，播放器初始取消静音，音量服从系统媒体音量和系统输出设备。切换素材、退出预览、进入后台或销毁页面后暂停并释放会话，恢复此前的 category / mode / options；微信接管为通话或录音配置后不覆盖。音频启动失败明确提示，实际出声需真机复测。

0.3.8 取消自动分流时的 Wi-Fi 名称不可用弹窗。蜂窝流量或读不到 SSID 时直接使用外网地址；家中 SSID 匹配仍使用内网，设置页主动检查权限的说明保留。NAS 连接或认证失败继续显示实际错误。

0.3.9 图片预览支持双指缩放（1–5 倍）、放大后拖动、双击放大至 3 倍及再次双击还原。放大期间不触发左右切图，缩回适配屏幕后恢复左右切换；切换图片、旋转或分屏尺寸变化时重置为适配屏幕。实况的静态照片也可缩放；播放实况、普通视频及 GIF 继续由各自播放器显示。预览图片仍使用既有解码尺寸限制。

后续开发其他微信插件可参考 [微信插件开发经验与复用指南](docs/微信插件开发经验与复用指南.md)，汇总工程结构、私有接口适配、真机调试、打包注入、典型故障和新项目交接清单。

0.4.0 普通视频默认使用 NAS 提供的流畅清晰度在线播放，优先 480p、其次 720p，缺少这两档时使用返回列表中可用的较小分辨率。先缓冲开始播放，不在打开预览时下载完整原视频；勾选「原图」切换为原视频完整下载预览。流畅模式需要 NAS 相册的转码能力；不可用时明确提示，可主动选择原视频，不静默下载大文件。视频发送仍使用已有完整素材准备与微信视频交接，不将低清预览流当作发送文件。

**0.4.3 当前视频预览：直接播放原视频，边下载边看。** 取消 480p 转码及页面预热；不再等待 NAS 创建转码任务，也不在预览开始前下载完整文件。NAS 需支持 HTTP Range，视频编码和容器需可被当前 iOS 播放。勾选“原图”只影响发送，不会重新加载预览；流式播放失败时可手动选择完整下载后预览。播放原始画质会消耗相应网络流量，缓冲进度表示当前播放位置附近已缓存时长。发送继续使用原有素材下载与微信发送流程。2026-11-02 用户在测试 iPad 上确认启动明显变快，画面、声音和拖动播放进度均正常。

## 使用

1. 打开聊天 → ＋ → 照片，选择“飞牛相册”。
2. 首次输入 NAS IP 和账号密码。只填 `192.168.2.126` 这类 IP 即默认 HTTP 5666；自定义端口或 HTTPS 可填写完整地址。
3. 点击照片预览，点击右上角圆圈勾选；右下角发送，可选原图。实况在预览页左下角点击播放；GIF 使用原始文件。
4. 在照片、收藏或相册内的照片列表右侧，上下拖动带箭头的滑块；浮层显示年月日，松开直接加载该日及更早照片。普通滑动时也显示当前日期，不需要先下载全部照片。相册封面列表不显示日期条。
5. 点击顶部 AI 搜索入口，在弹出的输入框中填写自然语言描述，再点“搜索”。搜索范围为当前 NAS 账号可见的全部照片；点击结果入口右侧的 × 恢复原列表。弹窗“取消”保留当前列表和查询。搜索结果仍可预览、勾选、原图发送，详情每批最多 60 项，保持 NAS 搜索顺序。
6. 右上角设置可更换 NAS、退出账号和清理已经完成发送的缓存。默认记住登录态，密码不保存。
7. 点击顶部“分类”，进入人物、地点或媒体类型；人物依赖 NAS 已生成人脸识别结果，地点依赖照片的地理信息。分类内仍可预览、勾选并发送。
8. 视频网格有“▶ 视频”和时长标识，原视频通过 HTTP Range 边下载边播放；勾选“原图”只影响发送质量，不重启预览。视频发送使用微信原生本地视频素材；不导入系统相册。大视频需要等待下载，发送准备中可取消。

AI 识别由 NAS 执行，需在飞牛相册中开启智能识别并安装模型。插件不上传照片给其他 AI 服务。模型缺失、准备中或数据不一致会显示明确提示；不自动安装或重置 NAS 模型。

“系统相册”保留微信原有入口。照片、GIF、实况和普通视频均使用私有缓存。视频预览不再依赖 NAS 转码；原视频和 RAW 文件能否解码取决于当前 iOS。无法解码会提示错误，不用静态封面代替视频发送。分类结果采用 NAS 查询排序并分页加载，目前不显示完整图库日期条。

## Dopamine 安装与卸载

通过 Sileo 打开 rootless deb 安装，随后完全退出并重新打开微信。也可复制到 iPad 后使用 root SSH 执行：

```sh
dpkg -i /var/tmp/WeChatFnAlbum-0.4.3-rootless.deb
killall WeChat
uiopen --bundleid com.tencent.xin
```

卸载：`dpkg -r org.ac.wechatfnalbum`，重新打开微信。安装包不替换微信主程序、不修改参考 IPA。旧版本测试包以相同包名覆盖升级。

## 免越狱签名注入

1. 在签名工具中导入自己的微信 IPA，导入 injection deb；若工具只支持 dylib，就选择对应 dylib。升级前删除旧 WeChatFnAlbum.dylib，再加入新版，避免重复注入。0.2.4 允许全能签修改 Bundle ID，主程序 CFBundleExecutable 保持 WeChat。
2. 确认 dylib 被复制到微信主应用的 `Frameworks` 中，资源 bundle 放在 dylib 同目录。不要只注入通知扩展。
3. 确认主程序添加加载路径，例如 `@executable_path/Frameworks/WeChatFnAlbum.dylib`；对主程序、插件及包内需要签名的其他代码一同重签名。
4. 保留 `NSLocalNetworkUsageDescription` 和允许 LAN HTTP 请求的 ATS 配置。提供的 8.0.76 IPA 以及测试机 8.0.75 都已包含这些配置。
5. 按签名工具流程安装。插件本身不链接越狱专用动态库，无需额外添加 libsubstrate。

不同签名工具的 deb 导入规则不同。若没有复制资源，可手动加入；核心界面使用系统图标与代码布局，不依赖外部图片。重新签名改变钥匙串权限组后，NAS 登录态可能需要重新建立。

若直接进入系统相册，先确认使用 0.2.4 或更新版本：0.2.3 在修改包名后会跳过初始化。如仍异常，可对签名导出的 IPA 运行 `python3 tools/check_injected_ipa.py /完整路径/签名输出.ipa`，核对 dylib、架构和主程序加载引用。库文件存在不等于被加载；应检查签名输出，而非原始参考 IPA。

## 构建与测试

环境：macOS、Xcode、Theos，iPhoneOS 16.5 SDK（本机 Theos 已有），ldid；Theos 自带 `dm.pl` 打包，不强制安装 dpkg-deb。

```sh
export THEOS="$HOME/theos"
./build.sh

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-test.txt
python tests/test_native.py
# 需先启动 iOS 模拟器；视频集成测试还需 ffmpeg。
python tests/test_browser_ui.py
python tests/test_stream_playback.py
```

`THEOS` 默认 `$HOME/theos`，可通过环境变量覆盖。`tests/test_native.py` 依赖 `requirements-test.txt` 中的 PyCryptodome 和 websockets，签名参考实现已放在本仓库的 `tests/protocol_reference.py`，不需要桌面客户端。测试编译并运行实际 Objective-C 协议客户端，使用合成账号和本地服务验证，测试钥匙串与正式服务名隔离。

开发自检：`make package FN_DEVICE_TESTS=1` 会在微信启动时用合成图片验证本地素材回调，结果写入插件缓存的 `asset-tests.json`。正式 `build.sh` 不设置此标志。`tools/inspect_ipa.py` 提取目标 IPA 的相关 ObjC 元数据；输入 IPA 不会被修改。可选 Frida 探测脚本只读取相关方法签名。

## 兼容和参考
